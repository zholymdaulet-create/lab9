# week09: камера моделі, LookAt, пернетақтамен жылжу

Сахна: бес куб (z = 0 … -4). Камера `camPos`, `camFront`, `camUp` айнымалыларымен басқарылады, `view = lookAt(camPos, camPos + camFront, camUp)`.

## Басқару
| Перне | Әрекет |
|---|---|
| W / S | алға / артқа |
| A / D | солға / оңға |
| Space / Left Shift | жоғары / төмен |
| Left Ctrl | жүгіру (x2 жылдамдық) |
| R | бастапқы орынға қайту |
| P | `camPos` консольге шығады |
| Esc | шығу |

## 1-тапсырма: екі нұсқаның айырмашылығы
- `lookAt(camPos, glm::vec3(0.0f), camUp)` — мақсат нүктесі тұрақты (координат басы). Камера W/S-те жақындайды-алыстайды, ал A/D басқанда бүйірге жылжиды, бірақ әрқашан координат басына қарап тұрады, сондықтан сахнаны айналып жүргендей болады (орбита).
- `lookAt(camPos, camPos + camFront, camUp)` — мақсат нүктесі камерамен бірге жылжиды, бағыт өзгермейді. Камера еркін ұшады.

**A пернесі екінші нұсқада камераны қайда апарады?** Камера бүйірге жылжиды, бірақ координат басына бұрылып қарап тұрады, сондықтан орбита бойымен айналғандай көрінеді.
**Орбиталық камера қашан пайдалы?** 3D модель көрсеткіштерінде (viewer), CAD/редакторларда, өнімді айналдырып көрсету кезінде, стратегия ойындарында.

## 2-тапсырма: жоғары-төмен
Таңдалған нұсқа: `camPos += speed * camUp` (камераның төбесі бойымен). Қазір камера еңкеймегендіктен екеуі бірдей. Ұшақ симуляторында `camUp` керек, себебі ұшақ еңкейгенде «жоғары» да бұрылады. Ойындағы адам үшін әлемнің Y осі (`vec3(0,1,0)`) керек, себебі жоғары қарап тұрсаң да секіру тік жоғары болады.

## 3-тапсырма: жүгіру
**`speed *= 2.0f` жолын dt-ге көбейтуден бұрын жазсаң, нәтиже өзгере ме?** Жоқ. Көбейту ауыстырымды: `(2.5 * 2) * dt = (2.5 * dt) * 2`. Нәтиже бірдей, әрі dt қатысқандықтан FPS-ке тәуелсіз болып қалады.
